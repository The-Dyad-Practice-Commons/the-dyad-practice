# Single-Home

## Index Line
> **Single-Home:** Keep every fact in exactly one home, and every structure-decision on exactly one *earned* axis. Everywhere else, **point** — a view that cites its source and never restates it. Rename at the home and leave a redirect; never sweep the records. Add a directory only once the content has already worn a path to it. The drift this kills: a fact or a structure-decision quietly spreading into a second home — a duplicate, a swept rename, a restated copy, a premature folder, a second hierarchy — which is exactly where audits go stale.

## The Move *(ordered, wu-wei-atomic steps)*:

*Facts —*
1. **one home per fact** — it lives in exactly one content-home; nothing restates it;
2. **views point, never restate** — every other mention is a derived *view*, marked as such ("cite the source, not this lens"), carrying a source-pin + a staleness check (a view older than its source is counterfeit-green);
3. **status lives at the home** — the home declares the fact's epistemic status (candidate / settled); views inherit it, never re-grade;
4. **rename at the home + redirect** — rename once at the home and leave a redirect; records keep the name they were written under (only a machine-identifier rename reaches downstream citations);

*Structure (the same rule, generalized) —*
5. **one physicalized axis** — key the tree to the single axis your read-path walks; carry orthogonal classifications as metadata, never as a second hierarchy;
6. **earned, not pre-drawn** — add a directory or axis only when content has already worn a path to it; default-by-rule over exhaustive pre-classification.


`dyad-bond` specializes the *structure* half (steps 5–6) with a `locus:` front-matter axis
(`inherited / built / lived`) carried as metadata over a lifecycle-keyed tree, plus a default-by-rule for
un-tagged files. **Both are un-booted (n=0) and held OUT of the ledger below** until they survive a reuse
or a cold boot (`prove-before-propose`). The Commons owns the general rule; the specialization is bond's,
and not yet proven. *(Orthogonality cut.)*

## Ledger

The accumulating evidence lives in `ledger/` — **one testimonial per file** (`<contributor-hash>-<n>.md`),
append-only. Weight = file count. See `ledger/3ab18bb7-n1.md` for the n=1 seed (dyad-bond, multi-cycle).

> **Breadth honesty:** the seed ledger is **single-dyad** (dyad-bond). The Commons' own `directory/`
> already embodies single-home for the registry — independent convergence, **but same lineage** (bond
> inherited from the form, so it is not a clean second derivation). Admission is **provisional — seeking a
> second testimonial**, ideally from a dyad that did *not* inherit from this root (the clean-independence
> falsifier). Depth ≠ breadth.
